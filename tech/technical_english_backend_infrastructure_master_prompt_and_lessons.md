## Lesson 01 --- A Typical Day as a Backend Developer

### English Reading

Every morning, I start my day by checking my tasks and reviewing the
latest updates from my team. Today, I'm working on a login bug in our
backend system. First, I check the application logs to understand what
happened. I can reproduce the bug on my local machine, so I start
investigating the root cause.

After that, I review the related API endpoint and check whether the
request body is properly validated. I also check the database query
because it seems to be taking too long. I think the issue might be
related to missing validation or an inefficient database query.

Once I find the root cause, I'll update the code and test the fix
locally. If everything works as expected, I'll deploy the changes to the
staging environment for further testing. I also need to make sure that
the fix doesn't affect other features.

At the end of the day, I'll update my task status and share the progress
with my team. If I can't finish the task today, I'll explain what's
blocking me and provide an estimated completion time.

### Nội dung trọng tâm

-   Daily task updates.
-   Investigating a login bug.
-   Checking application logs.
-   Reproducing a bug.
-   Reviewing API validation and database queries.
-   Testing locally and deploying to staging.
-   Reporting blockers and estimated completion time.

## Lesson 02 --- Debugging a Database Performance Issue

### English Reading

Yesterday, our team received a report that the application was running
slowly. Some users complained that loading the dashboard took too much
time. As a backend developer, I started investigating the issue.

First, I checked the application logs and found that several API
requests were taking longer than usual. After that, I checked the
database queries related to the dashboard. I noticed that one SQL query
was taking almost five seconds to execute. This was much slower than
expected.

I decided to investigate the query using the EXPLAIN command. The
execution plan showed that the database was performing a full table scan
instead of using an index. The table contained millions of records, so
scanning the entire table was inefficient.

To improve performance, I added an index to the columns used in the
WHERE condition. Then, I ran the query again and compared the execution
time. The query became much faster after adding the index.

Finally, I tested the API again to make sure the response time had
improved. I also checked whether the new index affected other queries.
After confirming that everything worked correctly, I shared the results
with my team and updated the task status.

This experience reminded me that database performance is an important
part of backend development. When an application becomes slow, we should
investigate the root cause instead of immediately changing the code.

### Nội dung trọng tâm

-   Application performance.
-   Slow API requests.
-   SQL query execution time.
-   EXPLAIN and execution plan.
-   Full table scan versus index.
-   Improving query performance.
-   Verifying API response time.

## Lesson 03 --- Managing Files and Permissions in Ubuntu Linux

### English Reading

As a backend developer, I often work with Ubuntu servers to deploy and
maintain web applications. One of the basic tasks is managing files,
directories, and permissions.

When I deploy a Laravel application, I usually create a project
directory under the web root or a specific application directory. Before
deploying the application, I need to make sure that the directory
structure is correct and all required files are in place.

Linux uses a permission system to control who can read, write, and
execute files. There are three main permission groups: the file owner,
the group, and other users. I can use the `chmod` command to change file
permissions and the `chown` command to change file ownership.

For example, the Nginx and PHP-FPM services need appropriate permissions
to access application files. However, I should avoid giving unnecessary
write permissions because this can create security risks. In a Laravel
application, the `storage` and `bootstrap/cache` directories need to be
writable by the application process.

Sometimes, an application cannot write log files or upload files because
of incorrect permissions. When this happens, I usually check the file
ownership and permissions first. I can use commands such as `ls -l`,
`chmod`, and `chown` to investigate the issue.

Managing permissions correctly is important for both application
security and system stability. I should always follow the principle of
least privilege, which means giving each user or service only the
permissions it actually needs.

### Nội dung trọng tâm

-   Ubuntu server file and directory management.
-   Linux permission groups: owner, group, others.
-   Read, write and execute permissions.
-   `chmod` and `chown`.
-   Laravel `storage` and `bootstrap/cache`.
-   Security risks of unnecessary write permissions.
-   Principle of least privilege.

## Lesson 04 --- Understanding Linux Processes and Services

### English Reading

When managing an Ubuntu server, I need to understand how Linux processes
and services work. A process is a running instance of a program, while a
service is usually a background process that provides a specific
function to the system or other applications.

For example, Nginx handles incoming HTTP requests, PHP-FPM processes PHP
scripts, and MySQL manages database operations. These services usually
run in the background without requiring direct interaction from users.

On Ubuntu, I often use the `systemctl` command to manage system
services. I can check whether a service is running, start or stop it,
and restart it when necessary. For example, if Nginx is not responding,
I can check its status and review the related logs to identify the
problem.

Sometimes, a service fails to start because of an incorrect
configuration or a port conflict. In other cases, the server may run out
of memory, causing some processes to consume too many system resources.
When this happens, I use commands such as `ps`, `top`, and `free` to
monitor running processes, CPU usage, and memory consumption.

I also need to make sure that important services start automatically
when the server boots. This is especially important for production
environments because applications should become available again after a
server restart.

Monitoring processes and managing services are essential skills for
backend developers and system administrators. By understanding how these
components work, I can troubleshoot server issues more effectively and
keep applications running reliably.

### Nội dung trọng tâm

-   Linux processes and services.
-   Background processes.
-   Nginx, PHP-FPM and MySQL services.
-   `systemctl`.
-   Service status, start, stop and restart.
-   Configuration errors and port conflicts.
-   CPU and memory monitoring.
-   Automatic service startup on boot.

## Lesson 05 --- Troubleshooting Network Connectivity

### English Reading

Yesterday, I received a report that one of our web applications was not
accessible. Some users could not open the website, while others
experienced connection timeouts. As a backend developer, I needed to
investigate the network issue and identify the root cause.

First, I checked whether the server was online and could connect to the
internet. I used the `ping` command to test network connectivity. After
that, I checked the DNS configuration to make sure the domain name was
resolving to the correct IP address. DNS problems can prevent users from
reaching a website even when the server is running normally.

Next, I checked whether the required ports were open. For example, a web
server usually needs ports 80 and 443 to handle HTTP and HTTPS requests.
I also reviewed the firewall rules to see if any connections were being
blocked. Sometimes, a service is running correctly, but users still
cannot access it because the firewall does not allow incoming traffic.

After checking the network configuration, I used the `curl` command to
send an HTTP request to the server. This helped me understand whether
the server could respond to incoming requests. I also checked the
application logs and Nginx error logs for additional information.

Finally, I found that the firewall was blocking connections on the
required port. I updated the firewall rules and tested the website
again. Everything worked as expected, and users could access the
application normally.

This incident reminded me that troubleshooting network issues requires a
systematic approach. I should check the server, DNS, ports, firewall,
and application services step by step instead of changing multiple
configurations at the same time.

### Nội dung trọng tâm

-   Network connectivity.
-   Connection timeouts.
-   Ping and DNS resolution.
-   IP address and domain name.
-   Ports 80 and 443.
-   Firewall rules and incoming traffic.
-   HTTP request with curl.
-   Nginx and application logs.
-   Systematic troubleshooting.

## Lesson 06 --- How Nginx Handles HTTP Requests

### English Reading

Nginx is a high-performance web server that handles incoming HTTP and
HTTPS requests. When a user visits a website, the browser sends a
request to the server. Nginx receives the request and determines how to
handle it based on the server configuration.

First, Nginx listens on specific network ports, usually port 80 for HTTP
and port 443 for HTTPS. When a request arrives, Nginx checks the
requested domain name, URL path, and other request information. It then
uses the matching server block and location block to decide what to do
next.

If the request is for a static file, such as an image, CSS file, or
JavaScript file, Nginx can serve it directly without involving the
backend application. However, if the request needs to be processed by a
PHP application, Nginx usually forwards it to PHP-FPM through FastCGI.

Nginx can also work as a reverse proxy. In this setup, it receives
requests from clients and forwards them to another application server.
For example, Nginx can forward requests to a Laravel application running
inside a Docker container. This allows the application server to handle
business logic while Nginx manages incoming connections.

After receiving the response from the backend service, Nginx sends the
response back to the client. If the backend service is unavailable or
takes too long to respond, Nginx may return an error such as 502 Bad
Gateway or 504 Gateway Timeout.

Understanding how Nginx handles HTTP requests is essential for backend
developers. It helps us configure web servers correctly, troubleshoot
connection problems, and improve application performance.

### Nội dung trọng tâm

-   Nginx as a high-performance web server.
-   HTTP and HTTPS.
-   Listening ports 80 and 443.
-   Server block and location block.
-   Serving static files.
-   Forwarding PHP requests to PHP-FPM through FastCGI.
-   Reverse proxy.
-   Laravel application behind Nginx.
-   502 Bad Gateway and 504 Gateway Timeout.
