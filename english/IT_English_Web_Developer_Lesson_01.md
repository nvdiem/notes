# 2. Core Vocabulary

## 2.1. Software development

| English | Vietnamese | Common phrases |
|---|---|---|
| application | ứng dụng | build an application |
| feature | tính năng | add a feature |
| requirement | yêu cầu | meet a requirement |
| task | nhiệm vụ/công việc | complete a task |
| issue | vấn đề/lỗi cần xử lý | fix an issue |
| bug | lỗi phần mềm | fix a bug |
| change | thay đổi | make a change |
| implementation | việc triển khai/thực hiện | feature implementation |
| maintain | duy trì/bảo trì | maintain an application |
| improve | cải thiện | improve performance |
| release | bản phát hành / phát hành | release a new version |
| develop | phát triển | develop a feature |
| implement | triển khai/thực hiện | implement a feature |
| test | kiểm thử | test the application |
| deploy | triển khai lên môi trường | deploy an application |

### Important distinction

**issue** và **bug** không hoàn toàn giống nhau.

- **bug**: một lỗi trong phần mềm.
- **issue**: vấn đề/công việc cần được xử lý; có thể là bug nhưng không nhất thiết.

Ví dụ:

> We found a bug in the login process.

> There is an issue with the payment service.

# 3. High-Frequency Sentence Patterns

Đây là phần quan trọng nhất của bài.

Không học từng từ riêng lẻ. Hãy học cả pattern.

## Pattern 1 — work on + noun

**work on something** = làm việc trên / đang xử lý một việc gì đó

> I am working on a new feature.

> The team is working on the payment system.

### Pattern

```text
work on + feature/task/project/system
```

---

## Pattern 2 — be responsible for + noun/V-ing

**be responsible for** = chịu trách nhiệm về

> The backend team is responsible for maintaining the API.

> She is responsible for testing the application.

### Pattern

```text
be responsible for + noun
be responsible for + V-ing
```

---

## Pattern 3 — need to + verb

**need to do something** = cần làm gì đó

> We need to fix this issue.

> We need to improve the performance of the application.

### Pattern

```text
need to + V
```

---

## Pattern 4 — be used to + verb

**be used to do something** = được sử dụng để làm gì

> This function is used to validate user input.

> The API is used to retrieve user information.

### Pattern

```text
be used to + V
```

---

## Pattern 5 — allow + someone + to + verb

**allow someone to do something** = cho phép ai đó làm gì

> This feature allows users to upload files.

> The API allows clients to retrieve data.

### Pattern

```text
allow + someone + to + V
```

---

## Pattern 6 — help + someone + verb

**help someone do something** = giúp ai đó làm gì

> This tool helps developers find bugs.

> Caching helps the application reduce database load.

### Pattern

```text
help + someone + V
```

---

## Pattern 7 — be working on + noun

Dùng để mô tả công việc đang thực hiện.

> I am currently working on the authentication feature.

> The team is working on a new version of the application.

---

## Pattern 8 — be required to + verb

**be required to do something** = được yêu cầu phải làm gì

> Developers are required to write tests for new features.

> Users are required to provide valid credentials.

---

## Pattern 9 — before + noun / clause

> We need to test the application before the release.

> Please review the code before you merge the branch.

---

## Pattern 10 — once + clause

**once** = một khi / sau khi

> Once the issue is fixed, we can deploy the application.

> Once the tests pass, the team can release the new version.

# 5. Grammar Focus — Present Simple vs. Present Continuous

Trong môi trường IT, hai thì này xuất hiện rất thường xuyên.

## Present Simple

Dùng để mô tả:

- chức năng
- sự thật
- trách nhiệm
- cách hệ thống hoạt động

> The application stores user data.

> The API returns JSON data.

> The team maintains the backend system.

---

## Present Continuous

Dùng để mô tả:

- việc đang làm
- task hiện tại
- công việc đang diễn ra

> I am working on a new feature.

> We are fixing a database issue.

> The team is preparing the next release.

### So sánh

> The team maintains the application.

= Đây là trách nhiệm/công việc thường xuyên.

> The team is maintaining the application.

= Đội đang thực hiện việc bảo trì vào thời điểm hiện tại.

---

## Reading Passage

> ### A Typical Day for a Web Developer
>
> A web developer usually works on several tasks during the day. Some tasks involve developing new features, while others involve fixing bugs or improving existing functionality.
>
> Before implementing a new feature, the developer needs to understand the requirements. The team may discuss the requirements with the product owner and other developers to make sure that everyone understands what needs to be built.
>
> Once the requirements are clear, the developer starts the implementation. The developer may need to modify the existing code, add new functions, and write tests for the new feature.
>
> After the implementation is complete, the code is reviewed by another developer. If the reviewer finds an issue, the developer needs to make the necessary changes. Once the review is completed and the tests pass, the team can prepare the feature for release.
>
> Developers also spend time maintaining existing applications. They investigate issues, fix bugs, improve performance, and update documentation. This work is important because software needs to be maintained after it is released.

> The development team is currently working on a new version of the web application. The main goal is to improve performance and add several new features. Before implementation, the team reviews the requirements and discusses possible technical issues.
>
> Each developer is responsible for implementing specific tasks. After completing a task, the developer writes tests and creates a pull request for code review. # 11. Reverse Translation

Sau khi hoàn thành phần trên, hãy dịch đoạn tiếng Việt này sang tiếng Anh.

> Nhóm phát triển hiện đang làm việc trên một phiên bản mới của ứng dụng web. Mục tiêu chính là cải thiện hiệu năng và thêm một số tính năng mới. Trước khi triển khai, nhóm xem xét các yêu cầu và thảo luận những vấn đề kỹ thuật có thể xảy ra.
>
> Mỗi developer chịu trách nhiệm triển khai một số task cụ thể. Sau khi hoàn thành task, developer viết test và tạo pull request để review code. Nếu reviewer phát hiện vấn đề, developer thực hiện những thay đổi cần thiết. Sau khi các test thành công và code được phê duyệt, tính năng có thể được đưa vào bản phát hành tiếp theo.

# 16. Key Principle

> **Don't learn English words. Learn how developers use English.**

Thay vì học:

```text
requirement = yêu cầu
```

hãy học:

```text
understand the requirements
meet the requirements
define the requirements
change the requirements
```

Thay vì:

```text
issue = vấn đề
```

hãy học:

```text
find an issue
report an issue
fix an issue
resolve an issue
```

Đây sẽ là nguyên tắc xuyên suốt cả 8 bài học.
