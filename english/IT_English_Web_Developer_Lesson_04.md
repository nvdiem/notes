### ask for clarification

> Could you clarify this requirement?

### raise a concern

> I have a concern about this implementation.

### address feedback

> I addressed your feedback in the latest commit.

### take a look

> Could you take a look at this function?

### make a change

> I made the requested changes.

### resolve an issue

> The issue has been resolved.

---

# 5. Reading — A Pull Request Review

> A developer creates a new branch before implementing a feature. After completing the implementation, the developer commits the changes and pushes the branch to the remote repository. The developer then creates a pull request so that other team members can review the code.
>
> During the review, another developer may leave comments about the implementation. Some comments may ask for clarification, while others may suggest changes to improve readability, performance, or maintainability.
>
> The original developer addresses the feedback and pushes additional commits. If the changes introduce a merge conflict, the developer needs to resolve the conflict before the pull request can be merged.
>
> Once the reviewers approve the pull request and all tests pass, the branch can be merged into the main branch.
